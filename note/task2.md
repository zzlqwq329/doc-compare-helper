# Task 2 学习笔记 · 匹配两版中原文相同的段落

对应代码是 [compare.py](../project/compare.py)，验收要求见 [Task 2](../docs/02-second-task.md)。输入由 [Task 1](task1.md) 生成。

## 函数做什么

| 函数 | 我的理解 |
| --- | --- |
| `group_by_text(blocks)` | 接收一版的段落列表，返回按原文分组的字典。键是 `raw_text`，值是包含这句原文的完整段落记录列表。V1 和 V2 各调用一次，各自分组。 |
| `compare_versions(v1_blocks, v2_blocks)` 的第一轮配对 | 两版里同一句原文各出现一次时才配对。章节相同记「未变」，章节不同记「移动」。`pairs` 记下分类和两端的完整记录，两个已配对编号集合用来筛出剩余段落。 |
| `main()` | 读取 `outputs/blocks-v1.json` 和 `outputs/blocks-v2.json`。用 `json.loads()` 把文件里读出的字符串转回 Python 列表，再交给对比函数。现在还会把完整结果写进 `outputs/comparison.json`。 |

样本在这一轮得到 **5 对未变、1 对移动**，V1 剩 **7 段**，V2 剩 **8 段**。这些是 Task 2 第一轮配对的数字。现在运行 `compare.py`，还会看到 Task 3 对剩余段落的处理结果。

## 我卡过的地方

- **还没建立分组字典就调用 `.get()`。** 在定义 `v1_groups` 或 `v2_groups` 之前查它，会报 `NameError`，意思是 Python 找不到这个名字。先读完两份 JSON，再分别用 `group_by_text()` 得到两份字典。循环里只给 `text` 赋值的话，循环结束时只留着最后一条原文。
- **分不清 `block` 和 `text`。** `block` 是整条记录，`text` 是从它取出的原文字符串。`groups[text]` 按原文这个键取出整组列表，再加 `[0]` 才取到列表里的第一条记录。`append(block)` 放进去的是完整记录。
- **以为重复的原文会分到两组。** 同一句原文只用一个键。第一次遇到这句话时创建空列表，之后每次遇到都往同一个列表追加。`append()` 放在 `if` 外面，第一次和以后出现的记录都会存下来。
- **把分组成功当成已经配对。** 比如 V1 里同一句话有两条，V2 只有一条，两版都能建组，但程序无法决定该选哪个 V1 编号，三条都留在未匹配列表。如果 V2 查不到同一句话，`.get(text, [])` 会给出空列表，也跳过配对。
- **把凭证保存条款看成了「未变」。** 它从 `V1-P011`（第三章 归档与监督）到了 `V2-P003`（第二章 报销与审批），原文相同但跨章，结果是「移动」。
- **把一对里的字段个数当成列表长度。** `pairs.append((status, old_block, new_block))` 把三个值作为一个元组存进去，一次 `append()` 只增加一对。两个 `set()` 集合则分别存两版已配对的编号，用 `in` 检查编号是否在里面。
- **把 V1 的剩余数量算成了 8 段。** 5 对未变加 1 对移动等于 6 对，每对用掉两版各一段，所以 V1 剩 `13 - 6 = 7` 段，V2 剩 `14 - 6 = 8` 段。
- **没看懂「未匹配」怎么筛。** 编号没进已配对集合，就保留整条记录。`V1-P003` 的「10 个工作日」和 `V2-P004` 的「5 个工作日」原文不同，所以各自留在未匹配列表。
