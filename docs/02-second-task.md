# 第二项练习：匹配两版中原文相同的段落

## 第一小步：找出未变和跨章节移动的段落

在 `project` 目录下创建 `compare.py`，和 Task 1 的 `reader.py` 放在一起。读取两份已生成的段落 JSON，按正文内容配对。今天先在终端打印配对结果和两版各自未匹配的段落，预计 60—90 分钟。

保存脚本后，在 PowerShell 中运行。

```powershell
Set-Location -LiteralPath 'D:\Java\文档分析项目'
python .\project\compare.py
```

## 为什么先做这一步

同一条制度在新版本里可能换了位置，段落编号也会变。先找出两版中原文完全相同的段落，就能确定哪些内容保留了下来，并把剩余段落交给下一步判断是否属于修改、新增或删除。

## 输入与输出约定

- 输入是 Task 1 生成的 `outputs/blocks-v1.json` 和 `outputs/blocks-v2.json`。每条记录用 `raw_text` 比较正文，用 `section` 判断章节，用 `block_id` 定位原段落。
- 配对结果输出分类和两版的 `block_id`。未匹配结果分别列出 V1、V2 的段落编号。程序内部保留完整记录，方便下一步继续比较正文和引用原文。

终端格式可以自行调整。下面展示两条配对和样本汇总。

```text
未变 V1-P001 → V2-P001
移动 V1-P011 → V2-P003
未变 5 对，移动 1 对
V1 未匹配 7 段，V2 未匹配 8 段
```

## 按这三个小步完成

1. 用 UTF-8 加载两份 JSON，先确认 V1 有 13 条、V2 有 14 条。若输出文件缺失，先重新运行 `python .\project\reader.py`。
2. 按 `raw_text` 找候选。只有同一正文在 V1 和 V2 各出现一次时才自动配对。两段的 `section` 相同记为「未变」，不同记为「移动」。同一正文在任一版本出现多次时，把对应记录留在两版各自的未匹配列表中，等后续处理。
3. 打印配对及剩余段落。检查每个输入段落都能在结果中找到，而且只出现一次。固定样本的编号和计数只用于验收，脚本根据实际输入计算结果。

## 验收清单

- [ ] 得到 5 对未变、1 对移动。V1 剩 7 段，V2 剩 8 段。
- [ ] 移动的是凭证保存条款，从 `V1-P011`（第三章 归档与监督）到 `V2-P003`（第二章 报销与审批）。
- [ ] 「10 个工作日」所在的 `V1-P003` 和「5 个工作日」所在的 `V2-P004` 都出现在各自的未匹配列表里。
- [ ] `block_id` 在结果中没有重复出现。V1 覆盖 6 个已配对段落和 7 个未配对段落，V2 覆盖 6 个已配对段落和 8 个未配对段落。

## 卡住时的提示

- 给同一正文下的记录分组时，可以想象一个字典，键是 `raw_text`，值是记录列表。列表长度告诉你该正文在这个版本出现了几次。
- 可以先请 AI 生成代码初稿。自己沿着凭证保存条款走一遍，找到程序在哪一步配对、在哪一步判断「移动」、在哪一步把已配对条款从剩余列表中排除。
