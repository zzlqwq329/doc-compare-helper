# Task 4 · Markdown 证据报告

## 1. 本轮唯一目标

让 `project/report.py` 把 Task 3 已生成的 `outputs/comparison.json` 转成一份能查回原文的报告 `outputs/comparison-report.md`。

## 2. 验收标准

JSON 是程序读取的对比记录。Markdown 是可以直接打开阅读的文本格式。这一轮把记录里的变化类型和原文位置排成报告。

- [ ] 在项目根目录运行 `.\.venv\Scripts\python.exe .\project\report.py`，命令成功结束并生成 `outputs/comparison-report.md`。该命令目前未验证。
- [ ] 用现有样本生成的报告有 **10 条变化明细**，包含 6 条修改、1 条移动、1 条删除和 2 条新增。5 条未变记录不进入变化明细。
- [ ] 每条原文证据都显示版本、段落编号、章节、行号和原文，内容与输入逐项一致。固定样本一共 **17 处引用**。
- [ ] 打开报告中的报销期限修改项，能回到 `samples/expense-v1.md` 第 11 行核对「10个工作日」，并回到 `samples/expense-v2.md` 第 13 行核对「5个工作日」。这项检查防止把旧版和新版的证据放反。
- [ ] 能用自己的话回答下方三个问题，并指出报告里哪一条可以拿来核对自己的解释。

## 3. 边界清单

- 报告直接使用对比记录里的 `type`（变化类型）、`old`（旧版证据）和 `new`（新版证据）。已有的变化类型和行号直接照录。
- 修改和移动引用两版。新增只引用新版，删除只引用旧版。JSON 中的 `null` 表示这一侧没有证据，报告跳过该侧。
- `needs_review` 表示程序还不能确定如何配对。遇到它就写「待核对」，并照录已有的证据。
- `fixtures/expected-changes.json` 是人工核对用的答案，报告生成程序只从 `outputs/comparison.json` 取对比结果。

## 4. 三个检查问题

1. 如果对比结果里报销期限的旧版证据是第 11 行，报告该从哪个字段拿这个数字？读者拿到数字后去哪里核对？
2. 如果一条删除记录的 `new` 是 `null`，报告应给出哪一版的哪几项信息？
3. 如果两版原文一字不差，但 Task 3 标为「移动」，这条是否出现在变化明细里？读者凭哪两项信息能看出来它确实移动了？

## 5. 上一轮遗留
