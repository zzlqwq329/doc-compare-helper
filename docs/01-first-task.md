# 第一项练习：让程序知道原文在哪里

## 第一小步：读取 V1 并打印行号

在项目根目录创建 `reader.py`，用 UTF-8 读取 `samples/expense-v1.md`。从 1 开始打印每行的行号和原文，标题和空行也照常打印。可以先尝试 30—60 分钟。

保存脚本后，在 PowerShell 中运行。

```powershell
Set-Location -LiteralPath 'D:\Java\文档分析项目'
python .\reader.py
```

- [ ] 第 1 行是文档标题，第 2 行是带行号的空行，第 3 行是 `## 第一章 总则`。
- [ ] 第 5 行是第一段正文，第 11 行包含“10个工作日”，中文显示正常。

卡住时，按“读取 → 拆成行 → 编号输出”逐步尝试。可用 `Path.read_text`、`splitlines` 和 `enumerate`。空行占据原文件行号，编号时保留它们。

## 为什么先做这一步

之后报告里会出现“提交期限缩短了”。为了核对这句话，程序必须知道它出自哪个版本、哪一章、哪一行。只保存清洗后的文字，后面就难以准确回到原文。

## 后续交付

第一小步通过后，再把两份样本的正文转成带版本、章节和行号的段落记录，分别保存到 `outputs/blocks-v1.json` 和 `outputs/blocks-v2.json`。

## 输入与输出约定

输入：`samples/expense-v1.md`、`samples/expense-v2.md`。

每个 JSON 文件顶层是包含全部正文段落的列表。下例只展示 V1 的第一条记录，V2 第一条的版本和编号对应换成 V2。

```json
[
  {
    "version_id": "V1",
    "block_id": "V1-P001",
    "section": "第一章 总则",
    "line_start": 5,
    "line_end": 5,
    "raw_text": "本制度适用于星河实验室全体成员的境内差旅报销。"
  }
]
```

样本中正文都是单行，所以 `line_start` 和 `line_end` 相同。以后支持多行段落时再扩展。

## 后续两步：分段并保存 JSON

1. 维护一个“当前章节”。遇到 `## ` 更新章节，遇到文档标题或空行跳过，遇到正文就创建一条记录。原文件行号与正文序号分开计数。
2. 把处理过程提取成函数，分别传入两个文件的路径和版本号 `V1`、`V2`。创建输出目录并以 UTF-8 保存 JSON，便于后续工具读取。

提取函数时，可以把脚本的运行入口放在 `if __name__ == "__main__":` 下，方便以后导入解析函数。

## 分段与 JSON 的验收清单

- [ ] V1 输出 13 条，V2 输出 14 条。
- [ ] 第一条正文定位到第 5 行；标题和空行没有混进正文。
- [ ] V1-P003 是第 11 行的 10 个工作日条款；V2-P004 是第 13 行的 5 个工作日条款。
- [ ] 凭证保存条款在 V1 属于第三章，在 V2 属于第二章。
- [ ] 摘录与对应文件的原文相等；清洗没有改变 `raw_text`。
- [ ] 相同文件重复运行，段落编号、章节、行号、正文一致。
- [ ] 路径不存在时明确报错，不能把失败伪装成“0 条正文”。
- [ ] 能解释为什么文件行号、正文序号、跨版本条款对应关系是三件事。

## 卡住时的提示

- 用 `startswith` 判断标题行，读取时继续使用原文件行号。
- JSON 中文可读性涉及 `ensure_ascii=False`，缩进可用 `indent=2`。
- `strip()` 适合判断空行；保存原文时使用只去掉换行的正文，避免丢失以后需要的空格。

## 交付给我什么

打印行号后直接说“检查第一小步”，我们先核对代码和输出，再继续分段。卡住时可以发运行命令和完整报错，或说明你停在哪一步。
